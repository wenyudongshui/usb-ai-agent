# usb-ai-agent · U盘私有化AI智能体

> Private AI agent on USB — encrypted & portable, zero host residue, password-gated.
> 基于U盘的私有化AI智能体：配置/密钥/人设/记忆加密随盘携带，本机零残留，GUI密码认证。

**版本 V4.0 · 纯U盘 + GUI密码版**：无需任何硬件令牌，一只 U 盘 + 一个密码即可运行，可直接整体实现。

---

## 项目概述

本项目构建一套**以 U 盘为唯一数据载体**的私有化AI智能体运行系统。全部配置文件、密钥、智能体人设与记忆数据仅存放于U盘；本地电脑仅作为临时运行载体，不持久化保存AI隐私数据。系统以 **GUI 密码作为唯一认证凭证**，支持多AI配置动态切换，并提供 **手动退出清理 + 拔盘兜底清理** 两级机制。

**使用场景**：在公共或临时电脑上使用个人AI助手，要求对话记录、API密钥、人设规则等敏感数据随U盘携带、输入密码才能使用、不遗留于所用电脑。

### 设计原则

- 能做自动的才自动：程序只对确定性可完成的动作做自动化处理；
- 做不到的明示给使用者：凡程序无法保证的清理动作，以明确的操作指引要求使用者手动完成；
- 安全边界诚实：在文档与界面中明确说明系统防护范围与不防护范围，不做超出能力的承诺；
- 单一凭证原则：认证只依赖一个GUI密码，不引入任何需要额外安装或驱动的硬件依赖。

### 安全目标边界

**系统防护目标：**

- 防止共用电脑的使用者翻看残留临时文件；
- 防止U盘丢失后他人直接读取配置与记忆（需密码；无密码时密文不可读）；
- 防止配置文件被单独复制后直接读出明文（AES-256-GCM，密钥被密码保护）。

**系统明确不防护的范围：**

- 专业取证环境与受监控电脑；
- 第三方API中转服务对对话内容的可见性；
- 口令强度不足导致的暴力破解（由密码策略与登录限速缓解）；
- 键盘记录器等恶意软件在运行期间窃取已解密会话内容。

## 快速开始

1. 准备一只 **U盘**（建议 8GB 以上，NTFS 或 exFAT），按下方目录结构放置文件；
2. 将便携 **Node.js**（Windows x64 免安装 LTS 版）解压到 `node\`；
3. 双击 `start.bat`，浏览器自动打开 `127.0.0.1:8787`；
4. **首次使用**：设置登录密码 → 添加第一个AI（模型API密钥）→ 开始对话；
5. 使用完毕：点击「保存并退出 / 不保存退出」→ 运行 `clean.bat` → 拔出U盘。

> 提示：正常运行无需管理员权限；建议将U盘程序目录加入杀软排除项。

## 技术方案

| 类别 | 选型 |
|---|---|
| 运行时 | 便携 Node.js（Windows x64 免安装 zip，LTS 版本） |
| 后端壳层 | Node.js 原生模块（http / crypto / fs / child_process / fetch），零第三方依赖 |
| GUI | 自研本地 Web 页面（HTML/CSS/JS）+ 127.0.0.1 本地服务器 |
| 加密方案 | AES-256-GCM（node:crypto），密文带随机 IV 与认证标签 |
| 口令派生 | scrypt（node:crypto 内置，N=2^15, r=8, p=1），派生约 0.2~0.5 秒 |
| AI 接入 | 兼容 OpenAI 协议（/chat/completions），node 原生 fetch |
| 清理 | clean.bat + 壳层 cleanup 模块 |
| 平台 | Windows 10 / 11（Node 跨 Win / macOS / Linux） |

## 系统架构

系统按三层组织：

1. **U盘层**：唯一数据源，存放启动脚本、便携 Node 运行时、加密配置、人设规则与记忆库；
2. **本机内存运行层**：Node 服务器在本机内存中运行，浏览器访问 127.0.0.1 页面完成交互，不向本机磁盘持久化业务数据；
3. **网络API层**：通过兼容 OpenAI 协议的大模型接口完成对话推理。

### 数据流

```text
双击 start.bat → 定位U盘盘符 → 启动 Node 服务器 → 打开浏览器进入登录页
登录页输入密码 → scrypt 派生 KEK → 解密主密钥（仅驻留内存）
选择AI → 解密 config.enc、读取 prompt.md → 构建会话上下文
对话经 /chat/completions 发送 → 响应返回内存会话数组
仅当使用者选择保存记忆时 → 会话摘要加密回写 memory.enc
退出 / 拔盘 → 触发清理，clean.bat 清除本机残留
```

### 密码认证与密钥派生链

```text
GUI密码 ──scrypt(N=2^15,r=8,p=1,salt=16B)──▶ KEK(32B) ──解密──▶ MasterKey(32B) ──AES-256-GCM──▶ config.enc / memory.enc
```

- 登录验证：`master.key.enc` 内含被 KEK 加密的 magic 校验串，能解开并校验通过即密码正确；
- 会话管理：登录成功后生成 32 字节随机 token（内存 Map 保存），httpOnly + SameSite=Strict Cookie 下发；受保护页面与全部 `/api/*` 一律校验 token，登出 / 退出 / 超时即销毁；
- 防爆破：失败响应延迟 0.5 秒，连续 5 次失败锁定 30 秒（内存计数）。

## 核心模块设计

### 加密与密钥管理

- 每个AI的 `config.enc` 与 `memory.enc` 均为 JSON 序列化后经 AES-256-GCM 加密，密文带随机 IV 与认证标签（GCM 可防篡改）；
- 主密钥为 32 字节随机数，首次启动生成，被 KEK 加密后存 `keys\master.key.enc`；
- KEK 由 GUI 密码经 scrypt 派生：密码错误无法解开主密钥，故「防整盘复制」与「防单文件读取」均由密码承担；
- 开发者模式可修改密码：旧密码解开主密钥 → 新密码重新派生 KEK → 重包装写回；
- 密钥与程序同盘且均为密文存储，本地电脑不落任何密钥明文。

### GUI 密码认证与会话管理

- 首次启动：`master.key.enc` 不存在 → 进入设置密码页（至少 8 位、含大小写与数字）→ 生成主密钥与 KEK；
- 登录：`POST /api/login` 校验通过发会话 token；连续 5 次失败锁定 30 秒；
- 会话：token 存内存 Map，10 分钟无操作过期，登出或退出销毁；
- 页面守卫：受保护页面（main/dev）未登录一律重定向登录页；`/api/*` 校验失败返回 401；
- 开发者模式：进入开发页需再次输入密码（二次校验），改密码、删记忆等敏感操作加确认。

### 多AI配置与隔离

- 扫描 `configs\` 目录识别全部 `ai_*`；
- 每个AI独立目录：`config.enc`（接口配置）、`prompt.md`（人设）、`memory.enc`（记忆），互不覆盖；
- 选择AI时解密对应 config，生成独立会话上下文（内存 `Map<aiId, messages>`）；
- 切换AI各会话相互独立；退出时释放全部解密数据。

### 人设与记忆

- 人设注入：读取所选AI的 `prompt.md` 全文作为 system 消息，注入角色定义、技能规则、输出范式与行为约束；人设模板仅来自U盘本地文件，不联网下载；
- 记忆存储：`memory.enc` 内存放消息数组 JSON；保存记忆时追加会话摘要（role=summary，含时间戳）；
- 记忆加载：会话开始时可将 `memory.enc` 内容注入上下文（由使用者选择是否携带历史）；
- 开发者模式提供记忆删除、导出与归档。

### 会话与三档清理

- 会话上下文仅驻留内存，结束即释放；
- 保存记忆：会话摘要加密写入 `memory.enc`；不保存记忆：内存上下文直接丢弃；
- 三档清理：正常退出全量清理、拔盘尽力清理、下次启动补清理；
- 清理机制：启动时将自用缓存目录路径写入 `keys\cache_path.txt`；`clean.bat` 读取该文件删除对应缓存目录及本机 workspace 残留；脚本不处理系统分页文件与系统日志。

### 开发者模式

- 口令二次校验进入开发者模式；
- AI 配置增删改查，保存前自动做最低成本连通性测试（max_tokens=1，不打印密钥）；
- Prompt 模板编辑；
- 记忆库删除、导出与归档；
- 密码修改与重置。

## 运行流程

### 首次启动

```text
插入U盘 → 双击 start.bat → 环境自检（node.exe 存在、磁盘可写）
→ 设置初始密码 → 配置向导（添加第一个AI的 API 密钥）→ 选择AI → 进入会话
```

### 正常使用

```text
双击 start.bat → 输入密码登录 → 选择AI → 建立会话
→ 对话（上下文驻留内存）→ 可随时切换AI（各AI会话相互独立）
```

### 退出（主路径）

```text
界面点击「保存并退出」或「不保存退出」→ 程序销毁会话、关闭网络连接、释放内存数据
→ 弹窗显示清理须知 → 使用者运行 clean.bat → 拔出U盘
```

### 拔盘兜底

```text
后台线程每 1 秒检测U盘盘符 → 检测到卷消失
→ 尽力清理内存并写入 keys\unclean.flag → 下次启动时提示运行 clean.bat 补清理
```

## 实现步骤（可分阶段交付）

五个阶段依次实施，每阶段可独立验收。全部完成后即为可整体运行的最小闭环。

### 阶段一：工程骨架与登录认证

**目标**：双击启动即可用，登录页能设置密码并验证，未登录无法访问任何页面。

1. 建立U盘目录结构：创建 `app\`、`node\`、`configs\`、`keys\`、`workspace\`，并放置占位的 `start.bat`、`clean.bat` 与 `README.txt`；
2. 部署便携 Node 运行时：从 nodejs.org 下载 Windows x64 免安装 zip（LTS，如 v22.x）解压到 `node\`，命令行验证 `node\node -v` 输出版本号；
3. 编写 `app\server.js`：`http.createServer` 监听 `127.0.0.1:8787`；按扩展名输出静态文件；路由分发 `/api/*` 走接口、其余走 `app\public\` 静态页；实现会话中间件（解析 Cookie 中的 token 并查询内存 SessionMap）；
4. 编写 `app\modules\crypto.js`：`randomKey()` 生成 32 字节；`encrypt/decrypt` 实现 AES-256-GCM（JSON 序列化，输出 `{iv, tag, data}` 的 base64 结构）；`deriveKEK(password, salt)` 实现 scrypt；
5. 编写 `app\modules\auth.js`：首次检测 `master.key.enc` 不存在 → 生成主密钥与随机 salt → deriveKEK → 加密写 master.key.enc，返回「需设置密码」状态；`login()` 校验 magic → 缓存 MasterKey 于内存 → 生成 token 会话；失败计数，连续 5 次锁定 30 秒；
6. 编写 `app\public\login.html`：密码输入框、错误提示；`GET /api/setup` 判断是否首次，`POST /api/login` 登录，`POST /api/logout` 登出；
7. 受保护页面守卫：main.html / dev.html 加载时调用 `GET /api/session`，未登录跳转登录页；`/api/*` 统一 401；
8. 编写 `start.bat`：`%~d0` 取U盘盘符 → 校验 `node\node.exe` 存在 → 后台启动 → 延时后 `open http://127.0.0.1:8787`。

**验收**：首次启动显示设置密码页；错误密码被拒且连续 5 次出现锁定提示；正确密码进入主页面；未登录直接访问 main.html 被重定向。

### 阶段二：加密与配置存储

**目标**：AI 配置加密落盘，配置向导可录入并进行连通性测试。

1. 编写 `app\modules\config.js`：`scanConfigs()` 遍历 `configs\` 识别 `ai_*\` 目录，读取 `config.enc`（解密）与 `prompt.md` 返回列表（API 密钥脱敏）；`readConfig/writeConfig` 封装加密读写；
2. 新建AI向导：表单录入（名称、BaseURL、模型、API密钥、可选温度）→ 生成 `ai_XXX\` 目录 → JSON 序列化后 AES 加密写 `config.enc`，生成默认 `prompt.md` 与空 `memory.enc`；
3. 连通性测试：`POST /api/test` → `fetch` 调用 `{baseURL}/chat/completions`，max_tokens=1，超时 10 秒；成功/失败提示，绝不打印密钥；
4. 加解密自检：直接打开 `config.enc` 应为 base64 密文而非明文 JSON。

**验收**：新建AI → 连通性测试通过 → 重启后仍能解密显示；`config.enc` 不可读明文；未登录调用 `/api/ais` 返回 401。

### 阶段三：多AI与会话聊天

**目标**：登录后可选择AI并完成对话，多AI会话隔离、人设生效。

1. 编写 `app\modules\ai.js`：`chat(ai, messages)` 调 `{baseURL}/chat/completions`，body={model, messages, temperature}，统一错误封装（超时 / 401 / 网络）；可选项：SSE 流式返回；
2. server.js 增加接口：`POST /api/ai/select`（记录当前AI并缓存解密结果）；`POST /api/chat`（组装 messages：system=prompt.md 全文 + 可选记忆 + 会话历史 → 调用 ai.chat → 追加到内存会话数组）；
3. 编写 `app\public\main.html`：顶部AI切换条（卡片列表）；人设摘要展示；会话区（消息气泡）、输入框、发送按钮、「保存记忆」开关；错误提示区（断网 / 密钥失效 / 限额）；
4. 会话上下文隔离：内存 `Map<aiId, messages[]>`，切换AI读写各自独立上下文；
5. 人设注入测试：在 `prompt.md` 写入角色规则，对话确认生效。

**验收**：登录 → 选择AI → 正常对话；切换AI后上下文互不串扰；人设生效；断网时报错清晰。

### 阶段四：记忆与开发者模式

**目标**：记忆加密持久化；开发者页完成配置增删改查、prompt 编辑、记忆管理与改密码。

1. 编写 `app\modules\memory.js`：`read(aiId)` 解密 memory.enc；`saveSummary(aiId, summary)` 追加 `{role:"summary", content, ts}` 并加密写回；导出、归档、清空接口；
2. 会话结束处理：点「保存并退出」且保存开关开启 → 生成会话摘要 → 加密写回；
3. 编写 `app\public\dev.html`：进入需二次输入密码；AI 配置列表 + 增删改查 + 连通性测试；Prompt 模板编辑器；记忆管理（查看 / 导出 / 归档 / 清空）；修改密码；
4. server.js 增加 `/api/dev/*` 路由，全部经「会话 + 开发者二次校验」双重守卫。

**验收**：保存记忆 → 重启后能加载历史；导出 JSON 可读；改密码后旧密码失效、新密码成功；删除某AI不影响其余。

### 阶段五：清理、拔盘兜底与打磨

**目标**：退出 / 拔盘不留残留，异常场景可控，交付物齐全。

1. 编写 `app\modules\cleanup.js`：`registerCachePath()` 启动时把自用缓存目录路径写入 `keys\cache_path.txt`；`cleanupLocal()` 删除所列出目录、清理本机 workspace 缓存、关闭活动连接；
2. 编写 `clean.bat`：读取 `cache_path.txt` 逐个删除并回显；附使用须知；不删系统分页文件与日志；
3. 退出流程：页面提供「保存并退出 / 不保存退出」→ 后端销毁会话、调 cleanupLocal → 前端弹窗提示运行 clean.bat 后拔出U盘；
4. 编写 `app\modules\usb.js`：后台线程每 1 秒检测U盘盘符，卷消失 → 尽力清理并写 `keys\unclean.flag`；
5. 下次启动检测：存在 unclean.flag → 登录后横幅提示补清理；
6. README.txt：启动方法、退出流程、清理须知、安全边界说明、FAQ、密码遗忘说明；
7. 界面打磨：统一样式；登录页展示安全提示。

**验收**：正常退出 → 本机 %TEMP% 无项目残留；直接拔盘 → 重启后出现补清理提示；clean.bat 可重复运行；杀软不拦截 start.bat（或已加入排除项）。

## 测试与验收

- **功能测试**：启动与环境自检；首次设密；登录 / 错误密码 / 5 次锁定；多AI切换；人设生效；保存与不保存退出；
- **清理验证**：退出后本机临时目录无残留；workspace 输出正常；拔盘后本机无业务文件；clean.bat 可重复运行；
- **安全验证**：未登录访问任何 `/api/*` 返回 401；三个 .enc 文件直接打开不可读明文；错误密码 5 次触发锁定；改密码后旧密码失效；
- **异常场景**：直接拔盘；断网；杀软告警；U盘写保护；Node 运行时缺失；端口被占用（自动递增换端口）。

## 风险与应对

| 风险 | 应对措施 |
|---|---|
| 杀软误报 | 代码签名（可选）、引导加入排除项、避免自毁类行为特征 |
| API 服务不可用或限额 | 多AI / 多密钥配置与故障转移 |
| 中转服务可见对话 | 界面明示云端可见性，敏感任务改走本地模型（如 Ollama） |
| U盘损坏或丢失 | 定期备份 workspace，提供记忆导出功能；密文不可解，丢失即需重新初始化 |
| 密码遗忘 | 明确说明：遗忘即数据不可恢复，需初始化重建；建议配合口令管理器保存 |
| 端口被占用 | 启动时探测空闲端口（8787 起递增）自动选取 |
| 多机混用 | 数据只在U盘、不落本机，天然无混用冲突 |

## 扩展方向（可选升级）

V4.0 为「纯U盘 + 密码」的最小完整闭环。以下扩展均以 V4.0 壳层为基座渐进叠加，不影响主线开发：

### 硬件方向

- **ESP32 硬件令牌 / 指纹**：恢复为可选的强认证因子，在密码之上叠加硬件校验（接入点：auth.js 增加二次校验环节）；
- **硬件安全芯片（SE）与 TPM 联动**：密钥防物理提取、U盘与本机双重认证；
- 语音交互、状态屏、断电保护等硬件扩展。

### 软件方向

- AI 技能插件系统（Prompt 与函数调用 schema 打包为插件）；
- 记忆向量检索（本地轻量 embedding，支持长记忆与相似回忆）；
- 智能路由（按任务类型自动选择模型，平衡成本与质量）；
- 会话导出迁移（标准格式导出，可跨设备继续）；
- 审计日志（仅写U盘并加密）。

### 场景方向

- 团队共用（多指纹多角色，各自隔离的AI配置与记忆）；
- 访客模式（无认证时仅开放只读公共AI）。
